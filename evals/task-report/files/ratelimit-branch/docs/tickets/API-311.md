# API-311 Rate limit the public API

Why: on 3 Sep one partner's retry loop sent about 4,000 requests a minute
to /v1/orders and the API stopped answering everyone else for 25 minutes.

## Acceptance criteria

1. Requests are limited per API key in one minute windows.
2. Over the limit the API answers 429 with a `Retry-After` header giving the
   number of seconds until the window resets.
3. The limit comes from the key's plan: Free 120 a minute, Pro 600 a minute.
   The numbers live in configuration, not in code.
4. Requests with no API key are limited per client IP at the Free rate.
5. Rejections are counted in a `ratelimit_rejected_total` metric labelled by
   plan, so support can see which partners hit the limit.
6. `RATE_LIMIT_ENABLED` switches the limiter off without a code change; it
   defaults to on.

## Out of scope

- Per-endpoint limits.
- Sharing counters across instances (one instance today).
