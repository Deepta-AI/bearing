# iOS guidelines

## Project shape

- The Xcode target under `App/` holds only what needs UIKit, SwiftUI or the
  bundle: the entry point, the composition root, views, assets, the privacy
  manifest and the String Catalog. Everything else lives in the local
  package `Packages/<Name>Kit` so it compiles and tests with `swift test`
  on Linux and macOS without Xcode.
- Package targets: `Core` (errors, Keychain, clock, shared value types),
  `Networking` (client, endpoints), `Features` (one folder per feature with
  its model, service and view model). Add a target when a feature gets a
  second consumer, not before.
- `project.yml` is the project. The `.xcodeproj` is generated by XcodeGen,
  git-ignored, and regenerated by `make generate`; a setting changed in
  Xcode's editor is lost on the next generate, so it never goes there.
- One feature folder has one reason to change and stays under 400 lines per
  file. `Utils`, `Helpers`, `Extensions+Everything` are findings.

## Toolchain choice

- Swift 6 language mode everywhere: tools version 6.0 and
  `swiftLanguageModes: [.v6]` in `Package.swift`, `SWIFT_VERSION` 6.0 in
  `project.yml`. Complete strict concurrency comes with the mode, and a data
  race is a compile error. The toolchain is Swift 6.3 (`swift:6.3.3` image
  on Linux CI, Xcode 26.6 from `.xcode-version` on macOS).
- An existing Swift 5 repository migrates module by module: enable
  `-strict-concurrency=complete`, clear the warnings, then flip that
  module's language mode. The package and the app move in one MR each.
- Unit tests use Swift Testing: `@Test` functions in a `struct` suite,
  `#expect` and `#require`, `#expect(throws:)` for errors. Tests run in
  parallel unless the suite is `@Suite(.serialized)`, which any suite that
  touches shared static state must be. XCTest stays for UI tests
  (`XCUIApplication` has no Swift Testing equivalent). Existing XCTest unit
  tests keep running beside the new ones; convert a file when it changes.

## State and views

- State flows down, events flow up. A screen owns its view model in
  `@State`; child views receive values and closures; a child never reaches
  up to mutate a parent's model.
- View models are `@Observable @MainActor final class` with
  `private(set)` state and `async` methods. No `ObservableObject`,
  `@Published`, `@StateObject` or `@ObservedObject` in new code; SwiftUI
  tracks `@Observable` per property, so the view re-renders less.
- Every screen state is an enum with `idle`, `loading`, `loaded`, `failed`
  (and `empty` when a collection can be empty), and the view switches over
  it exhaustively. A screen with only the happy path is not done.
- Work starts in `.task { await model.load() }` and, for a parameter,
  `.task(id:)`. Both are structured: leaving the screen cancels the work.
  An unstructured `Task {}` in `body` is a finding; in a button action it
  is fine because it is user-initiated and short.
- Derived values are computed properties on the model, never stored twice.
  The server cache (SwiftData) is the only copy of server data.
- Navigation: `NavigationStack` with a typed `path` owned by the screen
  that pushes; deep links append to that path after validation.

## Concurrency

- `@MainActor` on anything a view reads. Actors for shared mutable state
  (a cache, a session, a queue). Plain `Sendable` structs for everything
  else. `@unchecked Sendable` only with a lock and a comment naming it.
- `DispatchQueue`, `DispatchGroup`, semaphores and `Thread` do not appear in
  new code. Bridge a callback API once, with `withCheckedThrowingContinuation`
  and `withTaskCancellationHandler`, inside the package.
- Every long-lived `Task` has an owner that cancels it; `for await` loops
  check `Task.isCancelled`; a cancelled request surfaces as
  `AppError.cancelled` and the view ignores it.
- `[weak self]` in every escaping closure kept by something that outlives
  the view (notification observers, timers, stream continuations). Inside
  `.task` and structured child tasks a strong `self` is correct.

## Networking

- `URLSession` behind `APIClientProtocol`; endpoints are `Endpoint<Response>`
  values, so the return type is fixed at the call site. Features define
  their endpoints in an extension next to the model.
- Every call `async`, cancellable, with bounded timeouts from
  `URLSessionConfiguration.api()`. Decode with `Codable` and typed
  `CodingKeys` when the wire name differs; server enums carry an `unknown`
  case so a new value never breaks the app.
- Errors are `AppError` from the client outward; `isRetryable` decides
  whether the view offers a retry; `messageKey` picks the user string. Never
  show `localizedDescription` of a foreign error.
- Every request carries `X-Request-Id`; log it with the route and status,
  never the body, never the token.
- Certificate pinning on money and auth paths, through
  `URLSessionDelegate`, with the pin set in one place and a rotation task
  id next to it.

## Local data

- SwiftData for local persistence: first-party, no dependency, `@Model`
  and `@Query` integrate with SwiftUI and Observation, and the iOS 17 floor
  matches. GRDB was the alternative; its current major needs Swift 6.1 and
  Xcode 16.3, above this stack's floor, and its Linux support is
  community-only, so it would not have bought Linux tests either.
- SwiftData is Apple-only, so it lives in the App target or an
  `App/Persistence` folder behind `#if canImport(SwiftData)`. Repositories
  are protocols in `Core` with in-memory fakes; features and their tests
  never import SwiftData.
- Schema changes ship with a `VersionedSchema` and a migration plan from
  the first release on; a lightweight migration is still declared.
- Fetches are bounded (`fetchLimit`, predicates) and off the main actor
  when they can return more than a screenful.

## Secrets and configuration

- Tokens in the Keychain through `SecretStore`, accessibility
  `AfterFirstUnlockThisDeviceOnly`, service name the bundle id. Never
  `UserDefaults`, `@AppStorage` or a file.
- Configuration through xcconfig into `Info.plist`, read once in the
  composition root. `.env` feeds `Config/Local.xcconfig` for a machine;
  `Release.xcconfig` fixes production values in the repo.
- Signing lives in CI variables and `match`, never in the repo; the
  pre-commit hook blocks `.p12`, `.mobileprovision`, `.p8`.
- Universal links and URL schemes: check the host, the path shape and the
  signed-in user before navigating; unknown links open nothing.

## Accessibility and text

- Text styles (`.body`, `.headline`), never fixed point sizes; no fixed
  frames around text; layouts that survive the largest accessibility size
  (check with the Xcode accessibility inspector or an environment override
  in a preview).
- Every interactive element has an accessibility label; decorative images
  are `accessibilityHidden`; grouped rows use `.accessibilityElement
  (children: .combine)`; identifiers on elements UI tests touch.
- All user-facing strings live in `Localizable.xcstrings` with dotted keys
  (`health.title`), interpolations through format specifiers, never
  concatenation. `SWIFT_EMIT_LOC_STRINGS` keeps the catalog complete.

## Permissions and privacy

- Every permission has a usage string in `project.yml` before the code that
  requests it, phrased as what the user gets. Request at the moment of
  need, never at launch.
- `PrivacyInfo.xcprivacy` declares every required-reason API and collected
  data type, including those pulled in by a dependency. A missing entry is
  an App Store rejection, so it is a review item.

## Testing

- Logic, networking and view models are tested in the package with
  `swift test`: `URLProtocol` stubs for the client, protocol fakes for
  services, `FixedClock` for time, `InMemorySecretStore` for secrets. No
  sleeps, no network, no real Keychain, no simulator.
- View model tests cover every state transition, including the failure and
  the cancellation path.
- UI tests (`xcodebuild test`, `make test-ui`) exist for the flows that
  matter: sign-in, the money path, the first screen. They run on the macOS
  runner and use accessibility identifiers, never coordinates.
- Previews are part of the code: every screen has one per state, built from
  `AppContainer.preview(...)`.

## Style

- swiftformat and SwiftLint decide style; nothing a tool decides is
  discussed in review. `make fix` before every commit.
- Doc comments on every public type and function in the package.
- Types are named for what they are (`HealthViewModel`, `RemoteHealthService`);
  protocols for the capability (`HealthService`, `SecretStore`), not
  `HealthServiceProtocol`, unless the concrete type needs the plain name.
- Imports sorted; `import Foundation` only where Foundation is used;
  `#if canImport(FoundationNetworking)` wherever `URLSession` or `URLError`
  appears, so Linux keeps compiling.
