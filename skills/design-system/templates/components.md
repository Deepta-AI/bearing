# Component contract: <Product>

<!-- Template guidance: what each component may consume and how it must
     behave: variants, sizes, states, token roles, accessibility, and do
     and do not. Engineers read it to build components and screen-design
     copies its names verbatim into data-component attributes. The entries
     below are the kit's defaults: replace every placeholder with this
     system's values, and cut any component the product will never have,
     saying which in the report. Each entry's "- States:" line is one
     comma list of state names on one line, because
     scripts/system_page.py reads it to check that design-system.html
     draws every state in both themes; explanations go in "- State
     notes:". Delete each comment when you fill its section. -->

Generated by `design-system` from `docs/design/tokens.json`
v<version>. Every component below consumes tokens by role name and
nothing else. A component that needs a value the tokens do not have
gets a new token in `tokens.json`, never a literal.

Conventions used in every entry:

- Sizes: `sm` 32px, `md` 40px, `lg` 48px control height on web and
  desktop; mobile controls are `md` or `lg` (44pt minimum touch target).
- States: `rest`, `hover` (pointer devices only), `focus-visible`,
  `active`, `disabled`, `loading`, and where relevant `selected`,
  `invalid`, `checked`, `indeterminate`.
- Elevation: level 1 at rest and level 2 on hover for pressables;
  level 3 for overlays; 0 for everything else (the elevation rule).
- Focus: `focus.width` ring in the `focus` role with `focus.offset`,
  drawn with `outline`, never removed.
- Motion: state changes use `duration.fast` with `easing.standard`;
  entrances use `duration.base` with `easing.enter`; exits
  `duration.fast` with `easing.exit`; all zero under reduced motion.

## Button

<!-- What: the button contract: variants, sizes, states, token roles,
     accessibility, do and do not.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. One primary per view; the label is a verb
     and its object.
     Example: "Tokens: accent, accent-hover, on-accent (primary);
     radius.control 4px; elevation.1 rest, elevation.2 hover." -->

- Variants: `primary` (one per view), `secondary`, `ghost`, `danger`,
  `link`. Icon-only is a modifier, not a variant.
- Sizes: `sm`, `md`, `lg`.
- States: rest, hover, focus-visible, active, disabled, loading.
- Tokens: `accent`, `accent-hover`, `accent-active`, `on-accent`
  (primary); `surface`, `text`, `border-strong` (secondary); `danger`,
  `on-danger` (danger); `link` (link); `radius.control`; `space.2`
  horizontal padding at `sm`, `space.3` at `md` and `lg`; `font.roles.label`;
  `elevation.1` rest, `elevation.2` hover, `elevation.0` ghost and link.
- Accessibility: a real `button` (or `a` with `href` for link);
  icon-only carries `aria-label`; loading sets `aria-busy` and keeps the
  label; disabled stays focusable when it explains why (tooltip) and is
  otherwise removed from the tab order.
- Do: label with the verb and the object ("Save invoice"). Keep the
  same label through the flow.
- Do not: put two primaries in one view; animate width on hover; use
  `title` as the only label.

## Input

<!-- What: the text input contract, including helper and error text.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. A visible label bound by for; the error
     is linked by aria-describedby and never signalled by colour alone.
     Example: "States: rest, hover, focus-visible, disabled, read-only,
     invalid; error line reserved so nothing shifts." -->

- Variants: `text`, `email`, `number`, `password`, `search`, `textarea`,
  with optional leading icon, trailing action, prefix and suffix.
- Sizes: `sm`, `md`, `lg`.
- States: rest, hover, focus-visible, disabled, read-only, invalid.
- State notes: invalid always shows its error text; rest may show
  helper text.
- Tokens: `surface`, `text`, `text-muted` (placeholder and helper),
  `border`, `border-strong` (hover), `focus`, `danger` (invalid border
  and error text), `radius.control`, `space.2` padding, `font.roles.body`.
- Accessibility: a visible `label` bound by `for`; error text linked with
  `aria-describedby` and `aria-invalid="true"`; never placeholder as the
  label; `autocomplete` set for personal fields; `inputmode` for numeric.
- Do: show the error next to the field on blur and clear it on input.
- Do not: shift layout when the error appears (reserve the line);
  colour alone as the error signal.

## Select

<!-- What: the select and listbox contract, native or custom.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. Native select below 8 options; a custom
     listbox names the APG pattern it follows.
     Example: "Variants: native for the 5 clinic branches, searchable
     listbox for the 240 doctors." -->

- Variants: native `select` for under 8 options; listbox with search for
  more; multi-select renders chosen items as removable chips.
- Sizes: `sm`, `md`, `lg`.
- States: rest, hover, focus-visible, open, disabled, invalid.
- Tokens: as Input, plus `surface-raised` and `elevation.3` for the
  popup, `accent-subtle` for the highlighted option, `radius.overlay`
  for the popup, `z.overlay`.
- Accessibility: native select where possible; custom listbox follows
  the APG combobox pattern (`role="combobox"`, `aria-expanded`,
  `aria-activedescendant`, arrow keys, type-ahead, Escape closes).
- Do: keep the popup within the viewport; return focus on close.
- Do not: open on hover; trap focus in a non-modal popup.

## Checkbox and radio

<!-- What: the checkbox, radio and switch contract.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. Native inputs styled, a fieldset and
     legend per group, and a switch only for an immediate effect.
     Example: "Switch: 'Send SMS reminders' saves at once; checkbox:
     'Accept terms' waits for Submit." -->

- Variants: checkbox, radio, switch (a switch is immediate; a checkbox
  waits for submit), each with optional description.
- Sizes: one size, 20px box, 44px target.
- States: rest, hover, focus-visible, checked, indeterminate, disabled, invalid.
- State notes: indeterminate is checkbox only.
- Tokens: `border-strong` (unchecked), `accent` and `on-accent`
  (checked), `focus`, `danger` (invalid), `radius.control` for the box,
  `radius.full` for radio and switch, `duration.fast` for the check.
- Accessibility: native inputs styled, never a `div`; a group has a
  `fieldset` and `legend`; switch is `role="switch"` with `aria-checked`.
- Do: make the whole label clickable.
- Do not: use a switch for something that needs a Save button.

## Card

<!-- What: the card contract, static and pressable.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. Only a pressable card carries a shadow;
     cards are never the page layout and never nest.
     Example: "Pressable appointment card: one a covering the card, the
     patient name as its accessible name." -->

- Variants: `static` (a grouping surface) and `pressable` (the whole
  card is one link or button).
- Sizes: padding `space.3` compact, `space.4` default.
- States: rest, hover, focus-visible, active.
- State notes: a static card has rest only; the others are pressable.
- Tokens: `surface`, `border`, `radius.container`; `elevation.0` for
  static, `elevation.1` and `elevation.2` for pressable.
- Accessibility: a pressable card is one `a` or `button` covering the
  card with the heading as its name; nested interactive elements are
  not allowed inside a pressable card.
- Do: use a card when the group needs a boundary the layout does not
  already give.
- Do not: build a page out of stacked cards; put a shadow on a static
  card; nest cards.

## List row

<!-- What: the list row contract: plain, navigational and selectable.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. One primary action per row, leading
     elements aligned to one column.
     Example: "Sizes: md 56px for single-line patients, lg 72px when the
     next appointment shows as a second line." -->

- Variants: `plain`, `navigational` (chevron, whole row is a link),
  `selectable` (leading checkbox), with optional leading avatar or icon
  and trailing meta or action.
- Sizes: `sm` 40px, `md` 56px, `lg` 72px (two-line).
- States: rest, hover, focus-visible, selected, disabled.
- Tokens: `surface`, `border` (divider), `accent-subtle` (selected),
  `text`, `text-muted` (secondary line), `space.3` horizontal padding.
- Accessibility: a list is `ul` or `role="list"`; a navigational row is
  an `a`; a selectable row's checkbox has the row text as its label;
  trailing actions are reachable by Tab.
- Do: align leading elements to one column across rows.
- Do not: put more than one primary action in a row; make a row
  pressable and give it a separate action that is only on hover.

## Table

<!-- What: the table contract, including sort, selection, loading, empty
     and error.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. A real table with th scope and aria-sort;
     numbers right-aligned in tabular figures.
     Example: "Page above 200 rows; first column sticky below md." -->

- Variants: `data` (sortable, selectable), `simple` (read-only).
- Sizes: row height `sm` 36px, `md` 44px.
- States: rest, hover, selected, sorted-asc, sorted-desc, loading, empty, error.
- State notes: rest, hover and selected are per row; sorted-asc and
  sorted-desc per header; loading (skeleton rows), empty and error per
  table.
- Tokens: `surface`, `bg-subtle` (header), `border` (row divider),
  `accent-subtle` (selected), `font.roles.label` for headers,
  `font.roles.body` with tabular figures for cells, `space.2` cell
  padding.
- Accessibility: a real `table` with `th scope`; sort buttons inside
  headers with `aria-sort`; a caption or `aria-labelledby`; row
  selection through a checkbox column with a header select-all.
- Do: right-align numbers; keep the first column sticky on narrow
  screens; page or virtualise above 200 rows.
- Do not: collapse a table into cards below `md` without keeping the
  headers as labels; hide actions behind hover only.

## Dialog

<!-- What: the dialog contract: modal, alert and full-screen on mobile.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. Focus moves in and returns on close;
     Escape closes; one job per dialog; the primary button names the
     outcome.
     Example: "Alert: 'Cancel appointment?' with 'Keep appointment' and
     'Cancel appointment'." -->

- Variants: `modal` (blocks the page), `alert` (a decision, two buttons),
  `full-screen` on mobile below `sm`.
- Sizes: `sm` 400px, `md` 560px, `lg` 800px max width.
- States: opening, open, closing.
- Tokens: `overlay` (scrim), `surface-raised`, `radius.overlay`,
  `elevation.3`, `z.modal`, `space.4` padding, `duration.base` with
  `easing.enter` open, `duration.fast` with `easing.exit` close.
- Accessibility: native `dialog` with `showModal()` or
  `role="dialog"` with `aria-modal`, `aria-labelledby`; focus moves to
  the first control and returns on close; Escape closes; the scrim click
  closes unless the dialog holds unsaved input.
- Do: one job per dialog; the primary button names the outcome.
- Do not: stack dialogs; scroll the page behind an open dialog; open
  one on page load.

## Sheet

<!-- What: the sheet contract, bottom and side.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. The primary action is visible without
     scrolling the sheet; a decision belongs in an alert dialog instead.
     Example: "Side sheet 400px for appointment details at lg; bottom
     sheet up to 90vh on mobile." -->

- Variants: `bottom` (mobile default), `side` (desktop, `sm` or `md`
  width), with optional drag handle on mobile.
- Sizes: `bottom` at content height up to 90vh; `side` 400px or 560px.
- States: peek, open, dragging, closing.
- Tokens: as Dialog with `radius.overlay` on the leading corners only,
  `motion.easing.spring` for the drag settle.
- Accessibility: same as Dialog when modal; a non-modal side panel is
  `role="complementary"` and does not trap focus.
- Do: keep the primary action visible without scrolling the sheet.
- Do not: put a form longer than the viewport in a bottom sheet; use
  a sheet for a decision (that is an alert dialog).

## Toast

<!-- What: the toast contract: variants, timing, live region and action.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. Confirmation of a completed action only;
     at least 6 seconds, 10 when it carries an action.
     Example: "success: 'Appointment moved to 3:30 pm' with Undo,
     role=status, 10 seconds." -->

- Variants: `info`, `success`, `warning`, `danger`; with optional one
  action (Undo, View).
- Sizes: one, max width 400px.
- States: entering, visible, leaving, paused.
- State notes: paused while the pointer is over it or focus is in it.
- Tokens: `surface-raised`, `text`, the semantic role as a leading bar
  or icon (`success`, `warning`, `danger`, `info`), `radius.container`,
  `elevation.3`, `z.toast`, `duration.base` enter.
- Accessibility: the container is `role="status"` (`aria-live="polite"`)
  for info and success, `role="alert"` for danger; visible at least 6
  seconds, longer while hovered; an action is a real button reachable by
  a keyboard shortcut (F8 focuses the region).
- Do: use for confirmation of a completed action.
- Do not: use for errors that need a decision; show more than three
  at once; auto-dismiss one that carries an action in under 10 seconds.

## Tabs

<!-- What: the tabs contract: line, segmented and pill.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. The tablist, tab and tabpanel roles with
     arrow-key movement; never for sequential steps.
     Example: "Segmented: Day, Week, Month on the schedule, selection in
     the URL as ?view=week." -->

- Variants: `line` (underline indicator), `segmented` (pill group,
  up to 4 items), `pill` for filters.
- Sizes: `sm`, `md`.
- States: rest, hover, focus-visible, selected, disabled.
- State notes: per tab.
- Tokens: `text-muted` rest, `text` selected, `accent` indicator,
  `bg-subtle` segmented track, `surface` segmented selected,
  `duration.fast` indicator move (transform only).
- Accessibility: `role="tablist"`, `role="tab"` with `aria-selected`
  and `aria-controls`, `role="tabpanel"` with `aria-labelledby`; arrow
  keys move, Home and End jump, activation is automatic for `line` and
  `segmented`, manual (Enter) when panels load data.
- Do: reflect the selected tab in the URL when the page is shareable.
- Do not: use tabs for sequential steps; nest tabs.

## Navigation

<!-- What: the navigation contract: top bar, rails, side nav, bottom bar
     and breadcrumb.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. aria-current on the current item, a skip
     link first; no hamburger for primary navigation on desktop.
     Example: "Side nav 240px at lg with Schedule, Patients, Billing;
     bottom bar with the same three on mobile." -->

- Variants: `top bar` (marketing and small apps), `side rail` (icons,
  desktop apps), `side nav` (expanded, `lg` and up), `bottom bar`
  (mobile, three to five items), `breadcrumb`.
- Sizes: top bar 56px; side rail 64px wide; side nav 240px; bottom bar
  56px plus safe area.
- States: rest, hover, focus-visible, current, badged.
- State notes: per item; badged carries a count in the `accent` role.
- Tokens: `bg-subtle` (side nav surface), `text-muted` rest, `text`
  and `accent-subtle` current, `accent` badge, `border` edge,
  `z.sticky`.
- Accessibility: `nav` with `aria-label`; the current item has
  `aria-current="page"`; a collapsible nav has a button with
  `aria-expanded`; a skip link is the first focusable element on the
  page.
- Do: pair the nav with content on desktop so no half-width column
  stands beside empty space.
- Do not: hide primary navigation behind a hamburger on desktop; use
  more than five bottom bar items.

## Empty state

<!-- What: the empty state contract: first-run, no-results and error.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. It says what is missing and what to do
     next, with an action, in the product's voice; no apology.
     Example: "first-run: 'No appointments today. Book the first one.'
     with a Book appointment button." -->

- Variants: `first-run` (nothing yet, with a primary action),
  `no-results` (a filter or search found nothing, with a clear action),
  `error` (with retry).
- Sizes: `inline` (inside a panel) and `page`.
- States: first-run, no-results, error.
- State notes: one per variant; the empty state itself does not change.
- Tokens: `text` heading, `text-muted` body, `space.5` vertical
  rhythm, an illustration at most 160px using `accent-subtle` and
  `text-muted` only.
- Accessibility: heading level continues the page outline; the action
  is a Button; an error variant is announced through `role="status"`.
- Do: say what is missing and what to do next, in the product's
  voice.
- Do not: apologise; show a lonely icon with no action; use the
  error variant for an empty list.

## Skeleton

<!-- What: the skeleton contract for each component it stands in for.
     Good: every token named here exists in tokens.json by role name, never a
     literal; a value the tokens lack becomes a new token. Sized to its component so nothing moves
     when content arrives; static under reduced motion.
     Example: "row skeleton at 56px for the patient list, shown after
     300ms, kept at least 500ms." -->

- Variants: `text` (line), `block` (image or card), `row` (list or
  table row), `avatar`.
- Sizes: matches the component it stands in for, so nothing moves when
  content arrives.
- States: animating, static.
- State notes: animating is a 1.2s shimmer using opacity only; static
  is the same block under reduced motion.
- Tokens: `bg-subtle`, `radius.control` for text, the component's
  radius for blocks, `duration.deliberate` shimmer period.
- Accessibility: the region is `aria-busy="true"` and the skeleton is
  `aria-hidden`; a live region announces once when loading ends.
- Do: show a skeleton after 300ms of waiting, not immediately, and
  keep it at least 500ms once shown.
- Do not: use a skeleton for an action's pending state (that is the
  Button loading state); shimmer more than one region at a time.
